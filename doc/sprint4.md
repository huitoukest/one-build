# Sprint 4 实施计划（主干）：SVN 接入与合并推送

> 状态：主干草案，后续再细化。依赖 Sprint3 完成并验收通过。
> 依据：`需求文档.md` v1.2（**注意：文档 1.3 目前写「本期不做 SVN 实际合并与推送」，本迭代需同步修订该范围声明**）。

## 1. 迭代目标
在 Git 能力之外增加 SVN 来源：接入 SVN 仓库、浏览分支/路径、合并与冲突处理、推送，并把 SVN 纳入既有的项目/环境/步骤/任务体系，形成 SVN 场景闭环。

## 2. 闭环演示
添加 SVN 来源（凭证）→ 校验连通性 → 列分支/路径 → 选来源合并到目标路径 → 冲突检测与指引 → 提交推送 → 按环境执行步骤 → 部署后验证成功。

## 3. 功能范围（需求映射）

## 4. 关键设计要点
- 抽象 `RepoProvider` 接口（Git/SVN 实现），项目/合并/分支服务面向接口，避免 Git 专有逻辑外泄。
- SVN 无 git 的合并跟踪语义，需显式 `svn merge` + 冲突状态检测 + 人工解决后重试；不强制提交。
- 目标标识由「分支」泛化为「分支/路径」，`auto_branch` 与任务字段兼容 SVN 形态。
- 凭证复用 AES-GCM 加密与脱敏。

- SVN 项目复用环境/步骤/任务/锁/日志闭环。
