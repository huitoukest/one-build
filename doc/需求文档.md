# 需求文档：one-build 分支合并与构建编排工具

> 版本：v1.4
> 定位：本工具负责「分支自动合并 + 推送 + 按步骤编排构建/部署 + 接收回调 + 部署后验证」，不内置具体构建/部署逻辑，具体动作由用户配置的步骤完成。
> 部署形态：单机、单实例、内网运行。
> v1.3 修订：来源并入项目；项目回收站；环境 key 与默认变量；步骤详情独立页；URL 深链；任务步骤化展示；每步日志 3000 行；全局字号与时间格式。
> v1.4 修订：URL 定位符与导航回填；环境逻辑删除并隐藏；步骤详情页完整 CRUD + 工作空间结构树 + 命令说明；步骤序号改为 0 基；前序步骤输出通过 SpEL `#{steps[i].*}` 与 `OB_STEP_i_*` 暴露。

## 1. 概述

### 1.1 背景与目标

- 代码托管分散在多个 git 来源（自建 GitLab、GitHub、Gitee 或任意 git 地址），团队需要把多个开发分支快速合成一个可测试的临时分支，并触发构建/部署。
- 本工具提供 Web 界面：管理来源、凭证、项目、环境、步骤与验证配置；选择分支自动合并；把合并结果推回源仓库；按环境执行有序步骤（本地脚本 / HTTP / Jenkins）；接收 Jenkins 回调；全部步骤成功后探测目标服务是否可用。
- 一句话流程：**添加仓库 → 选分支 → 合并推送 → 按环境执行步骤 → 回调/退出码 → 部署后验证 → 成功**。

### 1.2 术语定义

| 术语 | 定义 |
|------|------|
| 来源（Source） | v1.3 起并入项目：仓库地址、地址类型、凭证直接由项目维护，不再单独管理来源 |
| 项目（Project） | 接入的业务项目，记录仓库地址、地址类型、凭证、基准分支、显示名、启用状态与回收站状态 |
| 回收站 | 删除的项目保留 30 天（可配），期间可恢复其步骤配置；到期彻底清理 |
| 环境 Key | 环境唯一标识，默认注入环境变量 `env={key}`；被步骤配置引用后不可修改 |
| 基准分支（Base Branch） | 合并的基线分支，默认 `master`，按项目配置 |
| 来源分支（Source Branch） | 用户在界面选入、需要合并的开发分支 |
| 目标分支（Auto Branch） | 由基准分支与来源分支自动合并生成的分支，前缀默认 `auto_merge/` |
| 环境（Environment） | 触发入口与部署目标；同一项目的不同环境可配置不同步骤 |
| 步骤（Step） | 项目+环境下的一个有序执行单元，类型为 SCRIPT / HTTP / JENKINS |
| 步骤结果 | 全局统一：`0=成功`、`1=继续轮询`、`其他=失败` |
| 轮询间隔 | 步骤返回 1 后再次尝试的等待时间，默认 2 秒，必须 ≥ 0；配置 0 时内部最小 100ms |
| 工作空间（Workspace） | 项目级持久目录，步骤在其中执行，保留依赖缓存 |
| 部署后验证（Verify） | 所有步骤成功后由本工具主动探测目标服务，判断是否可用 |
| 回调 | Jenkins 步骤调用本工具接口，上报步骤进度、日志与结果 |
| 外部 ID（externalId） | Jenkins 队列/构建号，或 HTTP 响应中的构建标识，用于关联与排查 |
| 项目锁 | 同一项目同一时间只允许一个非终态任务的互斥机制 |
| 强制取消 | 管理员取消任意非终态任务并释放项目锁 |
| `stage` / `failed_stage` | 任务阶段 / 失败阶段：MERGE、PUSH、PREPARE、EXECUTE、VERIFY |
| `failed_step_index` | 失败步骤序号 |
| 短哈希（suffix） | 目标分支名末尾的 6 位十六进制串，用于保证同名集合的唯一性 |

### 1.3 本期范围

**本期做**：

- 多项目接入（通用 git，本期实际可用文件路径；git http/ssh 字段预留）、凭证管理、项目添加与本地搜索。
- 分支列表、分支选择、自动合并、目标分支推送。
- 多环境，以及按「项目 + 环境」配置的有序步骤（SCRIPT / HTTP / JENKINS）。
- 全局步骤结果契约（0/1/其他）、每步可配轮询间隔、单步与整体超时。
- 项目级持久工作空间；本地与远程部署（脚本内 SSH，工具注入凭证）。
- 合并任务与触发任务、取消、强制取消、撤销、历史与日志。
- Jenkins 步骤回调（进度、日志、详情跳转、结果）。
- 项目级部署后验证（HTTP 探测 / 脚本探测）。
- 项目级互斥锁、启动恢复、状态-动作矩阵。
- 自动目标分支清理、任务与日志保留、项目回收站（30 天）、软删除、审计。
- 管理员与普通用户两种角色。
- 单机、单实例、内网部署与最小运维说明。

**本期不做**：

| 不做项 | 原因 |
|--------|------|
| 内置编译/打包/部署模板 | 具体动作由用户配置的步骤完成；工具只执行与监控 |
| 版本/commit 级部署校验 | 用户确认仅做健康检查；旧版本健康时可能误判，列入风险 |
| 制品管理、构建日志采集（非回调方式） | 由步骤输出或 Jenkins 回调提供 |
| SVN 实际合并与推送 | 仅预留 Provider 接口，本期界面不暴露 |
| 按账号远程检索仓库 | 本期仅通用 git，无平台 API，添加项目需提供仓库地址 |
| 灰度、蓝绿、金丝雀、多实例滚动发布 | 超出本工具职责 |
| 部署审批、部署冻结窗口 | 由外部发布平台负责 |
| 消息通知（钉钉/企微/邮件） | 非核心，后续可扩展 |
| 多节点/集群部署、双活 | 单机单实例；H2 文件库不支持多节点 |
| 反向代理、CA、公网 TLS 强制要求 | 内网 HTTP 运行，HTTPS 可选 |
| 主密钥自动轮换 | 本期通过配置更换并重新录入凭证 |
| 并行步骤、DAG、单步断点续跑 | 本期为顺序步骤流水线 |

## 2. 角色与权限

| 操作 | 管理员（ADMIN） | 普通用户（USER） |
|------|:---:|:---:|
| 登录、查看项目/分支/任务/日志 | 允许 | 允许 |
| 发起合并、撤销、触发、重新验证 | 允许 | 允许 |
| 取消任务 | 任意任务 | 仅自己发起的任务 |
| 强制取消（释放项目锁） | 允许 | 禁止 |
| 单步测试 | 允许 | 禁止 |
| 凭证、项目、环境、步骤、验证配置管理 | 允许 | 禁止 |
| 用户管理、审计日志查看 | 允许 | 禁止 |

- **管理员账号直接明文配置在 `application.yml`**；修改密码 = 修改 yml 后重启。配置文件权限必须为 `600`，日志与接口响应不回显密码。
- 普通用户由管理员在界面创建、禁用、重置密码；密码以 bcrypt 存储；禁用或改密后立即失效其会话。
- 登录态：服务端 Session + HttpOnly Cookie，`SameSite=Lax`；写操作校验 CSRF Token；会话超时可配（默认 8 小时）。
- 登录失败限流；连续失败可短暂锁定（参数可配）。

## 3. 核心流程与状态机

### 3.1 合并流程

1. 用户选择来源分支与部署环境，点击「部署 / 触发」；前端不再单独提供「合并」按钮，触发流程内部先执行本合并流程。
2. 获取项目锁（失败返回 `409`）。
3. 拉取最新远端引用，计算目标分支名。
4. 确保目标分支存在：不存在则从基准分支创建并立即推送。
5. 先合并基准分支（已最新则跳过），再按**字典序（ASCII 升序）**依次合并来源分支（已合入则跳过）。
6. 推送目标分支（禁止强制推送）。
7. 结束为 `MERGED`；冲突为 `CONFLICT`；其他错误为 `FAILED`；释放项目锁。

### 3.2 触发流程（步骤流水线）

1. 用户选择项目、来源分支与环境，点击「触发」。
2. 获取项目锁（失败返回 `409`）。
3. 执行 3.1 的合并流程；失败则终止，不执行步骤。
4. 若步骤中存在 SCRIPT 类型，准备项目级持久工作空间（`fetch`、检出目标分支、重置、保留 ignored 缓存）。
5. 按步骤序号依次执行 `SCRIPT / HTTP / JENKINS` 步骤。
6. 每步结果按全局契约：`0` 进入下一步；`1` 按间隔重试本步；其他则失败，剩余步骤标 `SKIPPED`。
7. 全部步骤成功后，若项目配置了验证，进入 `VERIFYING`；验证通过 → `SUCCESS`。
8. 任意环节失败/超时/取消 → 对应终态，释放项目锁。

### 3.3 状态机

合并任务（task_type = MERGE）：

```
PENDING → MERGING → PUSHING → MERGED
             ↘ CONFLICT        ↘ FAILED
任意非终态 → CANCELLED / INTERRUPTED
```

触发任务（task_type = TRIGGER）/ 重新验证（REVERIFY）：

```
TRIGGER:  PENDING → MERGING → PUSHING → PREPARING → EXECUTING → VERIFYING → SUCCESS
              ↘ CONFLICT        ↘ FAILED       ↘ FAILED / TIMEOUT
REVERIFY: PENDING → VERIFYING → SUCCESS / FAILED / TIMEOUT
任意非终态 → CANCELLED / INTERRUPTED
```

- 终态：`MERGED / SUCCESS / FAILED / TIMEOUT / CONFLICT / CANCELLED / INTERRUPTED`。
- 未配置验证时：步骤全部成功即为 `SUCCESS`。
- `failed_stage` 记录失败阶段（MERGE/PUSH/PREPARE/EXECUTE/VERIFY）；`failed_step_index` 记录失败步骤。
- 步骤状态：`PENDING / RUNNING / SUCCESS / FAILED / SKIPPED / CANCELLED / TIMEOUT`。
- `1` 轮询期间步骤保持 `RUNNING`，仅累加尝试次数。
- 终态不可变：终态后的回调只追加日志，不改变状态。
- 项目级锁保证同一项目不存在并行任务，因此不再需要"旧任务覆盖"类状态。

### 3.4 撤销与取消

- **撤销**：去掉某个来源分支（如 `a1_a2` 去掉 a2 → 只剩 a1），以新集合重新合并推送；**不执行步骤、不触发验证**。
  - 旧目标分支不立即删除，交由清理策略回收。
  - 仅允许对终态任务执行撤销；至少保留一个来源分支。
  - 撤销为新增任务，历史任务不删除，便于审计。
- **取消**：普通用户可取消自己发起的非终态任务；管理员可取消任意任务。
  - 终止当前步骤（杀死进程树 / 停止轮询 / 停止等待回调），任务置 `CANCELLED`，释放项目锁。
  - 已触发的外部构建无法停止，需到构建平台处理；其后续回调只记录日志。
- **强制取消**：管理员对任意非终态任务执行，语义同上，必须写审计日志。

### 3.5 项目互斥锁

- **范围**：项目级，覆盖合并 → 推送 → 准备 → 步骤执行 → 验证直到终态；跨环境互斥；不同项目可并行。
- **获取**：创建任务时在数据库事务内原子占用 `project_lock`；占用失败返回 `409`，响应包含占用任务 ID、操作人、开始时间。
- **释放**：任务进入任意终态立即释放。
- **强制取消**：管理员可强制取消占用任务并释放锁；外部步骤/构建可能继续运行。
- **启动恢复**：应用启动时把所有未终态任务标记为 `INTERRUPTED`，清空 `project_lock`；尽力终止记录过的步骤进程（孤儿进程），界面提示用户确认后重试。
- **单实例保护**：启动时获取 `one-build.lock` 文件锁，已存在其他实例则快速失败。
- **UI**：项目忙碌时禁用「合并 / 触发 / 撤销」，展示占用任务、操作人、开始时间与可执行动作。

### 3.6 状态-动作矩阵

| 状态 | 可执行动作 |
|------|-----------|
| PENDING / MERGING / PUSHING / PREPARING / EXECUTING / VERIFYING | 取消（本人/管理员）、强制取消（管理员）、查看 |
| MERGED | 触发、撤销、查看 |
| CONFLICT | 重试合并、撤销、查看（按冲突指引处理后重试） |
| FAILED | 重试（新建任务）、重新验证（仅验证失败）、查看 |
| TIMEOUT | 重试（新建任务）、重新验证（仅验证超时）、查看 |
| INTERRUPTED | 重试（新建任务）、查看 |
| SUCCESS | 撤销、重新验证、查看 |
| CANCELLED | 重试（新建任务）、查看 |

## 4. 功能需求

### 4.1 来源管理（v1.3 已并入项目）

- v1.3 起不再单独提供「来源」管理与来源表；仓库地址、地址类型、凭证直接挂在项目上。
- 地址类型：`FILE_PATH`（本期可用）、`GIT_HTTP`、`GIT_SSH`（字段预留，本期不做认证注入）。
- 历史来源能力（测试连接、凭证复用）由项目接口承接：项目保存时执行连通性校验，凭证可被多个项目复用。
- 凭证与项目解耦：一个凭证可被多个项目/环境复用。

### 4.2 凭证管理

- 认证方式：`TOKEN`、`SSH_KEY`、`USERNAME_PASSWORD`。
- 凭证密文使用 AES-GCM 加密后入库；主密钥来自配置或环境变量，不入库、不写日志。
- 接口与页面永不返回明文；编辑时留空表示不修改。
- 日志与异常统一脱敏（token、密码、私钥、Authorization 头）。
- 列表展示「最近测试时间 / 最近测试结果」；凭证失效时明确提示"凭证可能已过期"。
- 删除凭证前检查是否被项目/环境引用；被引用时禁止删除。

### 4.3 项目管理

- 添加项目：填写名称、仓库地址、地址类型、凭证（可选）、基准分支（默认 `master`）。
  - 文件路径类型保存前执行连通性校验（`git ls-remote`），失败给出明确原因；git http/ssh 本期仅预留字段。
  - **不支持按账号远程检索仓库**，必须提供仓库地址。
- 项目列表：左侧栏，按名称模糊搜索（大小写不敏感），按最后更新时间倒序；展示名称、最后更新时间、最后提交人、启用/禁用状态、忙碌标识。
- 项目详情：名称、仓库地址、地址类型、基准分支、最后更新时间、最后提交人、项目锁状态、当前目标分支。
- 元数据来源：本地 bare 仓库 `fetch` 后通过 `for-each-ref` 计算。
- 唯一性：`repo_url` 全局唯一；名称全局唯一（含已禁用与回收站项目）。
- 编辑：支持修改名称、仓库地址、地址类型、凭证、基准分支；项目忙碌时禁止修改仓库/基准分支/凭证。
- 禁用/启用：同一按钮按状态切换；禁用项目只能查看，禁止选入、部署、触发等写入或事件操作；禁用时级联禁用其步骤配置，启用时仅恢复由项目禁用导致的配置，不覆盖手工禁用。
- 删除：进入回收站，保留 30 天（可配置）；期间可恢复项目及其步骤配置；到期彻底清理。清理只删除项目、步骤配置、本地 bare/workspace，历史任务与日志保留用于审计。
- 新增「步骤详情」入口：跳转到该项目独立步骤详情页。
- 项目忙碌时禁止删除。

### 4.4 分支列表与选择

- 展示远端分支（不含目标分支前缀、不含基准分支），按最后提交时间新→旧排序，分页（默认每页 20，可配）。
- 基准分支不显示在分支列表中，显示在「项目锁」与「当前目标分支」之间。
- 每行：分支名、最后提交时间、最后提交人、[选入]/[已选入]。
- 已选集合在详情区展示，可逐个移除。
- 再次进入项目时，恢复最近一次成功触发/合并任务的来源分支；已选入分支按钮置灰显示「已选入」。
- 选择上限默认 20 个（可配）；来源分支为空或未选环境时「部署 / 触发」按钮禁用。
- 分支数据由本地 bare 仓库 `fetch --prune` 后读取；提供手动刷新；选入时校验分支仍存在。

### 4.5 自动合并

#### 4.5.1 目标分支命名

```
输入：基准分支 base、来源分支集合 S（按 ASCII 升序排序）

h_base = SHA-256(base)
h_i    = SHA-256(S[i])        // 每个来源分支单独哈希
h_all  = SHA-256(h_base + h_1 + h_2 + ... + h_n)   // 十六进制字符串拼接后再哈希
suffix = h_all 的前 6 位十六进制

slug   = S 以 "_" 连接，非法字符替换为 "_"
name   = 前缀 + slug + "_" + suffix
```

- 前缀默认 `auto_merge/`，可配置；必须以 `/` 结尾才能形成分组，否则配置校验报错。
- 示例：base=`master`，S=[a1,a2] → `auto_merge/a1_a2_9f2c1a`。
- 基准分支或来源集合任一变化 → `suffix` 变化 → 分支名变化，避免"同名不同内容"。
- 名称总长 ≤200 字符；超长时截断 `slug`，保留前缀与 `suffix`。
- 6 位哈希碰撞时自动延长到 8/10 位，仍冲突则报错。
- 分支名与 `slug` 需通过 git 引用合法性校验。

#### 4.5.2 合并执行

- 每个仓库维护一份 bare 缓存；临时合并工作副本按需创建，任务结束清理。
- 执行步骤：
  1. `git fetch --prune`；
  2. 若目标分支不存在：从 `origin/<base>` 创建并推送；
  3. `git merge --no-edit origin/<base>`（已最新跳过）；
  4. 按 ASCII 升序逐个 `git merge --no-edit origin/<source>`（已合入跳过）；
  5. 普通推送目标分支（禁止 `--force`），按来源平台设置抑制 CI 的选项。
- 复用：目标分支已存在时不删除重建，执行增量合并。
- 重试：以远端目标分支现状为准，`fetch` 后重置工作副本，再合并未合入分支。
- 同一仓库的 fetch/合并/分支读取/清理按仓库串行。
- git 身份：使用配置的 `user.name` / `user.email`。

#### 4.5.3 冲突与失败处理

- 任一合并冲突：
  1. 立即 `git merge --abort`；
  2. 终止后续合并，**不推送任何中间合并结果**；
  3. 任务置 `CONFLICT`，`failed_stage=MERGE`，记录冲突分支、冲突文件与日志；
  4. 不执行步骤；
  5. 界面展示目标分支完整名、冲突分支、冲突文件、可复制的处理命令与「重试合并」。
- 冲突处理指引见附录 B。
- 其他失败（推送被拒、认证失败、网络异常、磁盘不足）→ `FAILED`，记录原因；提示修复后重试。
- 重试合并复用同一目标分支，已合入分支自动跳过。

#### 4.5.4 推送与构建抑制

- 推送需要来源仓库写权限；权限不足时明确提示。
- 推送可能触发源平台流水线：
  - GitLab：`git push -o ci.skip`；
  - GitHub/Gitee：合并提交信息追加 `[skip ci]`；
  - 其他：可配置推送选项或提交标记，无法抑制时界面提示。
- 若步骤使用 Jenkins 且该分支配置了 SCM 自动触发，建议关闭自动触发或按分支过滤，避免与工具触发重复。

#### 4.5.5 项目级持久工作空间

- 路径：`<home>/workspace/<projectId>/`，跨任务复用。
- 每次触发任务准备：
  1. `git fetch --prune`；
  2. 检出目标分支；
  3. `git reset --hard`；
  4. `git clean -fd`（**不加 `-x`**，保留 ignored 文件，如 `.m2`、`node_modules`、构建缓存）。
- 步骤共享同一 workspace；编译产物可直接供后续部署步骤使用。
- 项目锁保证同一项目不会并发使用 workspace；不同项目使用不同目录。
- 工作目录限制在 workspace 内，禁止 `..` 越界。
- 失败保留现场；下次任务准备时重置；磁盘不足提前失败。
- 无 SCRIPT 步骤（仅 HTTP/JENKINS）时，可跳过工作空间准备。

### 4.6 环境管理

- 环境由管理员在界面增删改查（如 test1、test2），支持编辑、启用/停用与排序；环境 tab 为管理页第一个子 tab。
- 环境新增唯一 `key`（仅字母、数字、点、下划线、中划线），作为环境唯一标识；默认注入环境变量 `env={key}`。
- 环境新增说明列；可配置一组默认环境变量，优先级：内置 `OB_*` > 步骤自定义变量 > 环境默认变量 > 注入的 `env={key}`。
- 环境仅作为触发入口与部署目标，**不参与目标分支命名**；同一来源集合在不同环境下共用同一目标分支。
- 环境可配置远程目标：`targetHost`、`targetPort`、`targetUser`、`targetCredentialId`（SSH 凭证）、`knownHosts` 策略（strict / accept-new）。
- 项目页环境平铺展示：仅显示该项目已配置步骤的环境；当前选中环境高亮并追加 `(当前选中)`，其余灰色待选；禁用环境置灰不可选。
- 删除环境前校验是否有项目步骤配置引用；存在引用时禁止删除。`key` 被引用时禁止修改。
- 环境软删除（启用/禁用）；有运行中任务或步骤配置引用时禁止物理删除。

### 4.7 步骤配置与执行

#### 4.7.1 模型与配置

- 粒度：**项目 + 环境**。
- 一个触发配置包含有序步骤列表，最少 1 步。
- 每步字段：
  - 序号 `stepIndex`（从 0 开始，按升序执行）；
  - 名称；
  - 类型：`SCRIPT` / `HTTP` / `JENKINS`；
  - 单步超时 `timeoutSeconds`（默认 600，可配）；
  - 轮询间隔 `pollIntervalSeconds`（默认 2，必须 ≥ 0，单位秒；JENKINS 不适用）；
  - 工作目录 `workdir`（相对 workspace，默认 `.`，禁止越界）；
  - 环境变量（键值对；敏感值可用 `${secret.NAME}` 引用，加密存储、运行时注入、日志脱敏）；
  - 类型相关配置（见 4.7.3–4.7.5）；
  - 启用状态。
  - 添加人/添加时间、更新人/更新时间。
- 管理页「步骤配置」改为表单筛选列表（环境 + 项目名称），行操作：步骤详情、复制配置。
- 独立「步骤详情」页（非 tab）：默认查看指定项目+环境的已有配置；支持新增、更新、删除、禁用/启用、上移/下移、单步测试；命令单元格点击弹窗滚动查看。
- 步骤详情页进入规则：URL 可只带项目（`#/steps/{projectId}`），页面自动选择该项目已有配置的环境；未选择环境时明确提示；无配置时新增步骤自动创建配置。
- 步骤详情页右侧「项目结构」小窗：展示当前项目工作空间实际目录（未部署时提示先部署），支持逐层进入、上一级/面包屑返回、复制相对路径/绝对路径、一键填入工作目录。
- 命令输入框下方提供「命令说明」，包含 SpEL 前序步骤输出说明与示例。
- 复制配置：将当前配置复制到选定环境；目标环境已存在该项目配置时提示并失败，不覆盖。
- 触发配置头部可配置整体超时 `overallTimeoutSeconds`（默认 3600），超过则任务 `TIMEOUT`。
- 顺序执行；任一步失败即终止，剩余步骤标 `SKIPPED`；不支持并行、DAG、单步重跑（完整重试为新任务）。

#### 4.7.2 全局结果契约与轮询

所有步骤类型与部署后验证统一：

| 结果 | 含义 | 下一步 |
|------|------|--------|
| `0` | 成功 | 进入下一阶段 |
| `1` | 继续轮询 | 等待 `pollIntervalSeconds` 后重试本步 |
| 其他 | 失败 | 终止，剩余步骤 `SKIPPED`，任务 `FAILED` |

- **轮询间隔**：每步独立配置，默认 2 秒，整数，必须 ≥ 0。
  - 配置 `0`：界面显示 0，内部实际等待 `max(0, 0.1s)`，即最小 100ms，避免忙等。
  - 正数：按配置秒数等待。
  - 负数：保存与接口校验直接拒绝。
- **JENKINS 步骤**：回调驱动，轮询间隔字段不生效，界面标注"不适用"。
- 每次尝试记录：attempt、实际等待时长、结果码、摘要；轮询期间步骤状态保持 `RUNNING`。
- 单步超时从本步首次开始计时；`1` 持续到超时则步骤 `TIMEOUT`、任务 `FAILED`（或整体超时 `TIMEOUT`）。
- 步骤全部成功后进入验证（若配置）。

#### 4.7.3 SCRIPT 步骤

- 执行方式：`ProcessBuilder`；命令为字符串，按 OS 包装：
  - Linux：`sh -c "<command>"`；
  - Windows：`cmd /c "<command>"`；
  - 可配置 `shell` 覆盖（如 `bash`、`powershell`）。
- 命令内容由用户按执行服务器的 OS 书写（管道、重定向、变量展开均生效）。
- 工作目录：workspace 下的 `workdir`；越界拒绝。
- 环境变量：
  - 内置：`OB_PROJECT`、`OB_REPO_URL`、`OB_BASE_BRANCH`、`OB_AUTO_BRANCH`、`OB_SOURCE_BRANCHES`、`OB_ENV`、`OB_TASK_ID`、`OB_WORKSPACE`、`OB_COMMIT_SHA`、`OB_ATTEMPT`；
  - 前序步骤：`OB_STEP_COUNT`、`OB_STEP_{i}_NAME`、`OB_STEP_{i}_STATUS`、`OB_STEP_{i}_EXIT_CODE`、`OB_STEP_{i}_OUTPUT`（`i` 为 0 基序号；单变量最多 8000 字符，总量预算 24KB，超出保留尾部）；
  - 远程目标（若环境配置）：`OB_TARGET_HOST`、`OB_TARGET_PORT`、`OB_TARGET_USER`、`OB_SSH_KEY_PATH`、`OB_KNOWN_HOSTS`；
  - 管理员自定义环境变量与密钥引用。
- 模板：命令与环境变量值支持 Spring EL 模板 `#{...}`（`SimpleEvaluationContext` 只读数据绑定，禁止类型引用/构造器/Bean），可读取前序步骤结果：
  - `#{steps[0].output}`、`#{steps[0].exitCode}`、`#{steps[0].status}`、`#{steps[0].name}`、`#{steps.size()}`；
  - `#{task.autoBranch}`、`#{task.autoCommitSha}`、`#{env['JAVA_HOME']}`；
  - 引用未执行步骤、语法错误或越权表达式时，该步骤直接 `FAILED` 并在 `errorMsg` 给出表达式片段与原因；
  - `OB_*` 系统变量不参与表达式渲染，避免步骤输出中的 `#{` 被二次求值；单步测试无前序步骤结果。
- 输出传递：每步 stdout/stderr 合并输出（脱敏后）保留尾部，作为后续步骤 `OB_STEP_{i}_OUTPUT` 与 `#{steps[i].output}` 的来源；同时落库到任务步骤摘要供页面查看。
- 结果：进程退出码直接作为步骤结果（`0/1/其他`）。
- **返回 1 会重新执行同一命令**；脚本必须幂等，否则会重复执行副作用。
- 输出：合并 stdout/stderr，按行写入任务日志，带步骤标记与时间戳；每步仅保留前 3000 行（可配），并叠加单步字节上限（默认 2MB），先到者截断。
- 进程管理：超时/取消时杀死进程树；脚本若启动后台服务，必须自行重定向 stdout/stderr 到文件并关闭继承管道，否则可能导致步骤不结束。
- 工具链：JDK/Maven/Go/Node 等由管理员通过环境变量或系统 PATH 提供；可在执行前做命令存在性预检（可选）。

#### 4.7.4 HTTP 步骤

- 配置：方法、URL、请求头（敏感值加密）、请求体（支持模板变量）、单次请求超时、轮询间隔、单步超时、判断表达式。
- URL、请求头、请求体均支持模板变量与 `${secret.NAME}` 密钥引用；渲染后执行，日志脱敏。
- 执行：每次尝试发送 HTTP 请求；将 `status`、`body`、`headers` 交给管理员配置的 **Spring SpEL** 判断表达式。
- 表达式必须返回整数：`0` 成功、`1` 继续轮询、其他失败；非整数或求值异常按失败处理并记录。
- 上下文变量：
  - `#status`（int）、`#body`（String）、`#headers`（Map）、`#attempt`（int）、`#elapsed`（long，秒）；
  - `#env`、`#project`、`#autoBranch`、`#taskId`。
- 示例：

```text
#status == 200 && #body.contains('"state":"done"') ? 0
  : (#status == 202 || #status == 404 ? 1 : 2)
```

- **安全**：使用受限的 `SimpleEvaluationContext`，禁止 Bean/类型/静态引用与任意对象方法调用；仅允许字符串/Map 的受控方法（如 `contains`、`startsWith`、`get`）；仅管理员可配置；限制表达式长度。
- 每次尝试重复请求同一 URL；**接口幂等由执行方负责**（可能出现重复触发）；建议请求体携带 `taskId`/`stepIndex` 作为幂等键。
- 响应体摘要（截断、脱敏）写入日志。
- 适用：简单同步接口、可查询状态的异步构建服务。

#### 4.7.5 JENKINS 步骤

- 配置：基础地址、Job 名、参数模板、可选凭证、单步超时、整体超时。
- 触发：调用 Jenkins 触发 Job，参数包含项目、仓库、目标分支、环境、任务 ID、`stepIndex`、回调地址与回调令牌；触发成功返回队列 ID（`externalId`）。
- 完成判定：**等待 Jenkins 回调**，不使用轮询间隔。
  - 回调 `status=RUNNING` → 步骤保持运行，记录日志，重置空闲计时；
  - `SUCCESS` → 结果 0；
  - `FAILED` → 结果 2（或回调直接提供 `resultCode`）。
- 空闲超时与整体超时：长时间无回调按单步超时失败；整体超时不可突破。
- 日志：回调 `message` 追加到步骤日志；`detailUrl` 作为详情链接。
- 重复触发：推送目标分支可能触发 Jenkins SCM 构建，需在 Jenkins 侧关闭自动触发或过滤 `auto_merge/*`。
- 触发成功不等于构建成功；以回调为准。

#### 4.7.6 远程部署

- 工具本身只执行本地命令；远程部署由 SCRIPT 步骤内的 SSH/发布工具完成。
- 环境配置目标主机、端口、用户、SSH 凭证、known_hosts 策略。
- 工具把目标信息与 SSH 私钥以环境变量/临时文件注入脚本：
  - 临时私钥权限 `600`，步骤结束删除；
  - known_hosts 按策略生成/校验；
  - 目标信息与凭证在日志中脱敏。
- 本地环境可不配置目标主机，脚本按本地路径执行。

#### 4.7.7 失败、超时与取消

- 步骤返回非 0/1：步骤 `FAILED`，任务 `FAILED`，`failed_stage=EXECUTE`，`failed_step_index` 记录序号，剩余 `SKIPPED`。
- 步骤超时：步骤 `TIMEOUT`，任务 `FAILED`（或整体超时 `TIMEOUT`）。
- 取消：终止当前进程树/轮询/回调等待；步骤 `CANCELLED`，任务 `CANCELLED`；释放锁。
- 失败任务保留 workspace 现场（按天数）；下次任务准备时重置。
- 重试：新建任务重新执行全部步骤；不提供从失败步骤续跑。

#### 4.7.8 单步测试

- 管理员可对单个步骤执行「测试」：
  - `SCRIPT`：在从 bare 缓存创建的**临时工作空间**中执行一次，避免污染项目持久 workspace；
  - `HTTP`：发送一次请求并返回判断结果；
  - `JENKINS`：仅校验参数渲染与连通性，不触发构建。
- 测试执行需项目锁空闲；结果写入审计日志；测试不产生正式任务记录（或标记为 TEST）。

### 4.8 回调

#### 4.8.1 回调协议

请求体（JSON）：

```json
{
  "id": 123,
  "token": "一次性回调令牌",
  "stepIndex": 1,
  "status": "RUNNING",
  "resultCode": 1,
  "totalSteps": 3,
  "currentStep": 1,
  "externalId": "jenkins-queue-456",
  "detailUrl": "https://jenkins.example.com/job/deploy/123/",
  "message": "步骤说明或日志片段"
}
```

规则：

- 仅 `JENKINS` 步骤使用回调；`SCRIPT`/`HTTP` 不需要回调。
- 校验任务 ID、`stepIndex` 与令牌（常量时间比较），失败返回 `401/403`。
- `status` 枚举：`RUNNING`、`SUCCESS`、`FAILED`。
- `resultCode` 可选；不传时按 `RUNNING=1`、`SUCCESS=0`、`FAILED=2` 映射。
- `RUNNING`：更新步骤日志与 `externalId`，保持运行，重置空闲计时。
- `SUCCESS`：本步结果 0，进入下一步（全部完成则进入验证/成功）。
- `FAILED`：本步失败，任务 `FAILED`，剩余 `SKIPPED`。
- `message` 追加到步骤日志（限制单次长度，防日志膨胀）。
- `detailUrl` 仅允许 `http/https`，长度 ≤2048；前端只做链接展示。
- 终态不可变：终态后的回调只追加日志；`CANCELLED`/`INTERRUPTED` 不可覆盖。
- 重复/乱序回调幂等：同一 `stepIndex` 的进度只前进，不回退。

### 4.9 撤销

- 入口：任务详情或项目当前目标分支；以最近一次成功合并的来源集合为准。
- 操作：选择要去掉的来源分支 → 生成新集合 → 新建合并任务 → 合并推送 → 结束 `MERGED`。
- 不执行步骤；旧目标分支保留，等待清理。
- 页面明确提示：撤销只改变后续合并结果，**不影响已触发的构建/部署**。
- 撤销为新增任务，历史任务不删除。
- 项目忙碌时禁止撤销。

### 4.10 取消与强制取消

- 普通用户可取消自己发起的非终态任务；管理员可取消任意任务。
- 取消时终止当前步骤（进程树/轮询/回调等待），任务 `CANCELLED`，立即释放项目锁。
- 外部构建继续运行，后续回调只记录日志。
- 强制取消（管理员）需二次确认，记录操作人、原因、时间到审计日志。
- 取消后工作空间按保留策略处理。

### 4.11 目标分支清理

- 每日定时任务执行（默认凌晨 3 点，时区可配）。
- `lastUsedAt = max(目标分支最后提交时间, 最近一次被合并/触发任务引用时间)`。
- 删除条件（同时满足）：
  1. `now - lastUsedAt > 30 天`；
  2. 不在该项目按 `lastUsedAt` 排序的最近 10 个目标分支内；
  3. 当前没有被运行中的任务引用。
- 删除远端分支并更新本地记录（标记 `DELETED`）；失败记录日志；写审计日志。
- 保留数量与天数均可配。

### 4.12 任务历史与日志

- 任务列表：按项目名称模糊、类型（自动合并 MERGE / 手动步骤 TRIGGER）、状态、分支（来源或目标）筛选；分页；展示来源分支、目标分支、状态、耗时、操作人。
- 任务详情 URL 可一键复制，复制后可直接打开对应任务（hash 深链 `#/task/{id}`）。
- 任务详情采用双时间线：
  - **工具阶段**：合并 → 推送 → 准备 → 执行 → 验证，含起止时间与 `failed_stage`；
  - **步骤时间线**：首行为「自动合并」，其后为业务步骤；每步展示类型、状态、尝试次数、结果码、退出码、起止时间、耗时与日志按钮。
- 日志：按任务/步骤增量拉取（`afterId`），每步最多返回 3000 行；弹窗滚动展示，INFO/WARN/ERROR/DEBUG/TRACE 加粗；内容脱敏。
- 保留：任务与日志默认保留 180 天，超期清理；可配。

### 4.13 用户管理

- 管理员创建普通用户、禁用/启用、重置密码。
- 用户名全局唯一；普通用户密码 bcrypt；禁用或改密后立即失效会话。
- 不允许删除最后一个管理员；管理员角色不可在界面授予普通用户。
- 管理员账号仅来自 yml，界面不提供修改入口。
- 用户管理操作写审计日志。

### 4.15 部署后验证

#### 4.15.1 配置（项目级）

- 验证配置挂在项目上，可选；未配置或停用时步骤全部成功即为 `SUCCESS`。
- 类型：
  - `HTTP`：URL（模板变量）、方法、请求头（敏感值加密）、请求体、期望状态码（默认 200）、内容判断（无/包含/正则）或 SpEL 判断表达式、确定性失败状态码（默认 401/403）、是否跟随重定向（默认否）、响应体上限（默认 64KB）。
  - `SCRIPT`：命令、参数、工作目录、环境变量；退出码 `0=成功`、`1=继续轮询`、其他失败。
- 轮询间隔：默认 2 秒，必须 ≥ 0；配置 0 时内部最小 100ms。
- 整体超时：默认 300 秒，可配。
- 模板变量：`${env}`、`${project}`、`${repoUrl}`、`${baseBranch}`、`${autoBranch}`、`${sourceBranches}`、`${taskId}`。
- 提供「测试验证」按钮：执行一次探测并返回摘要（脱敏）。
- 配置在任务创建时快照。

#### 4.15.2 判定规则

- 成功：期望状态码/内容满足，或脚本 `exit 0`。
- 立即失败：命中确定性失败状态码/失败内容，或脚本退出码为 `0/1` 之外。
- 继续重试：网络错误、请求超时、5xx、内容暂不匹配、脚本 `exit 1`。
- 超时：到达整体超时仍不满足 → `TIMEOUT`（`failed_stage=VERIFY`）。
- **不校验版本/commit**（已确认）：若旧进程仍健康，可能误判成功；需要用户在部署脚本中自行保证新旧替换与版本正确性。
- 失败/超时均不自动回滚、不反向通知构建平台；界面提示"构建成功但服务不可用"。

#### 4.15.3 执行与日志

- 仅触发任务/重新验证任务在所有步骤成功后进入 `VERIFYING`；合并任务不验证。
- 单任务串行轮询，不重叠请求；每次尝试记录序号、耗时、状态码/退出码与响应摘要（截断、脱敏）。
- 验证全程占用项目锁；可取消。

#### 4.15.4 重试与重新验证

- **重新验证**：构建已成功、仅验证失败/超时/复检时，可发起 `REVERIFY` 任务，复用原目标分支与步骤结果，不重新执行步骤；需获取项目锁。
- **完整重试**：新建触发任务，重新合并、执行全部步骤与验证。
- 重新验证与新任务均保留原任务记录。

## 5. 数据模型（H2 文件库）

- 默认位置：jar 包同级目录，库名 `one-build-h2`，实际文件 `one-build-h2.mv.db`；可用 `ONE_BUILD_HOME` 覆盖数据根目录。

## 8. 非功能与异常

| 类别 | 要求 |
|------|------|
| 单实例 | 启动时获取 `one-build.lock` 文件锁；失败快速退出并提示 |
| 项目锁 | 项目级全周期互斥；创建任务原子占用；终态释放；忙时 `409` |
| 启动恢复 | 未终态任务标记 `INTERRUPTED`，清空项目锁；尽力终止记录的步骤进程 |
| 并发 | 不同项目可并行；同一仓库的 fetch/合并/分支读取/清理按仓库串行 |
| 步骤超时 | 单步超时 + 整体超时；超时杀进程树/停止轮询/停止等待，记录 `failed_step_index` |
| 取消 | 终止本地子进程；外部构建不可停止；取消后释放锁与工作空间策略 |
| 轮询 | 每步独立间隔，默认 2s，≥0；0 时内部最小 100ms；JENKINS 不适用 |
| 进程管理 | 记录步骤 PID；取消/超时杀进程树；启动恢复尽力清理孤儿进程 |
| 日志 | 步骤 stdout/stderr 合并入库，每步最多前 3000 行（可配）+ 单步字节上限（默认 2MB）；应用日志按天滚动 |
| 网络（内网） | 出站 git、HTTP 步骤、验证地址可达；Jenkins 可访问 `callback-base-url` |
| 远程部署 | 通过环境目标与 SSH 凭证注入脚本；临时私钥 600、用后删除 |
| 数据目录 | 启动校验可写；磁盘不足提前失败；失败工作空间保留可配天数 |
| 备份恢复 | 停机复制 `one-build-h2.mv.db`；恢复时停机替换 |
| 结构升级 | 开发阶段不兼容旧表结构，`schema_version` 仅记录当前版本；上线前需重新初始化数据 |
| 数据保留 | 任务与日志保留 180 天（可配），超期清理 |
| 软删除 | 项目删除进入回收站（30 天可配，到期清理项目/步骤配置/本地缓存，历史任务与日志保留）；环境启用/禁用；有运行中任务或步骤配置引用时禁止物理删除 |
| 时区 | 调度与展示统一使用配置时区（默认 Asia/Shanghai） |
| 审计 | 需求要求的审计表本期未启用，配置变更/清理/恢复/单步测试以运行日志记录替代 |

## 9. 安全设计

- 管理员密码：明文配置在 yml；文件权限 `600`；日志、接口、异常均不回显；修改需重启。
- 普通用户密码：bcrypt（cost ≥ 10）；禁用或改密后递增 `session_version`，旧会话立即失效。
- 凭证：AES-GCM 加密，主密钥来自配置或环境变量；密文与明文均不写日志；接口不返回明文。
- 步骤配置中的请求头、token、环境变量密钥等敏感值加密存储；日志脱敏。
- SpEL：使用受限 `SimpleEvaluationContext`，禁止 Bean/类型/静态引用与任意对象方法调用；仅允许字符串/Map 的受控方法；仅管理员可配置；限制表达式长度；求值异常按失败处理。
- 命令执行：SCRIPT 步骤仅管理员可配置；命令内容由管理员负责；参数/变量通过环境变量注入，避免拼接注入；以服务运行用户执行；工作目录限制在 workspace。
- 远程：临时私钥 `600`、用后删除；known_hosts 策略可配；目标信息与凭证脱敏。
- 验证探测：仅允许 `http/https`；默认不跟随重定向；限制响应体大小；仅管理员可配。
- Web：Session + HttpOnly Cookie + `SameSite=Lax`；写操作校验 CSRF Token；登录失败限流。
- 回调：一次性随机令牌，常量时间比较；`stepIndex` 校验；终态不可变；`detailUrl` 只做展示。
- 传输：内网 HTTP 可运行；如条件允许建议启用 HTTPS。

## 10. 验收标准

### 10.1 基础与权限

1. 管理员使用 yml 中明文账号密码登录；修改 yml 并重启后新密码生效。
2. 普通用户由管理员创建；禁用或改密后旧会话失效；普通用户无法访问配置与审计。
3. 管理员可新增来源（git）、三种凭证、项目（URL），并可测试连通性。

### 10.2 合并与工作空间

4. 项目列表支持模糊搜索，展示来源标识、最后更新时间、最后提交人、忙碌标识。
5. 分支列表按提交时间新→旧分页展示，可[选入]/[移除]，超过上限被拒绝。
6. 选择 a1、a2 合并 → 生成 `auto_merge/a1_a2_<6位哈希>` 并推送；不同顺序结果一致。
7. 去掉 a2 撤销 → 生成 `auto_merge/a1_<6位哈希>`，不执行步骤，旧分支保留待清理。
8. 基准分支有新提交后再次合并 → 目标分支包含最新基准内容。
9. 冲突 → `CONFLICT`、`failed_stage=MERGE`、不推送中间结果、不执行步骤、列出冲突文件与可复制命令。
10. 人工解决冲突后重试 → 复用目标分支、跳过已合入分支并成功。
11. 持久 workspace 每次触发前重置并保留 ignored 缓存；步骤共享同一目录。

### 10.3 步骤与轮询

12. 步骤按项目+环境配置，最少 1 步；支持 SCRIPT/HTTP/JENKINS，顺序执行。
13. 任一步失败 → 任务 `FAILED`、`failed_step_index` 正确、剩余步骤 `SKIPPED`。
14. SCRIPT 退出码 0 → 下一步；1 → 按间隔重跑命令；其他 → 失败。
15. HTTP 步骤 SpEL 返回 0 → 下一步；1 → 按间隔重新请求；其他 → 失败；表达式异常 → 失败。
16. JENKINS 步骤回调 RUNNING 保持运行、SUCCESS 进入下一步、FAILED 终止；回调带 `stepIndex`/`externalId`。
17. 每步轮询间隔默认 2s；配置 0 时实际约 100ms；负数保存/接口被拒绝；JENKINS 步骤该字段不生效。
18. 单步超时、整体超时生效；超时终止并记录失败步骤。
19. 单步测试在临时工作空间执行，不污染持久 workspace。
20. 远程目标信息与 SSH 凭证注入脚本且日志脱敏。

### 10.4 项目锁与恢复

21. 项目忙时新任务返回 `409 PROJECT_BUSY`，展示占用任务与操作人。
22. 管理员可强制取消任意任务，释放锁并写审计日志；外部构建继续运行。
23. 应用重启后未终态任务为 `INTERRUPTED`，项目锁清空，可重新发起。
24. 启动第二个实例被文件锁拒绝。
25. 取消运行中任务会终止当前步骤并释放锁。

### 10.5 回调与验证

26. 构建工具按协议回调 → 步骤进度与日志更新；最后一步成功后进入验证或直接成功。
27. HTTP 验证期望状态/内容满足 → `SUCCESS`；确定性失败码 → `FAILED`；持续不可达 → `TIMEOUT`。
28. 脚本验证 `exit 0` 成功、`exit 1` 继续轮询、其他失败。
29. 验证间隔默认 2s、可配 ≥0；0 时内部最小 100ms。
30. 验证失败/超时后可「重新验证」，复用步骤结果，不重新执行步骤。
31. 验证只做健康检查，不校验版本/commit（已知限制）。

### 10.6 运维与安全

32. 数据目录不可写时启动失败并提示路径；停机备份后可恢复。
33. 任务与日志保留 180 天后清理；被历史任务引用的来源/项目/环境禁止物理删除。
34. 日志与接口响应中不出现 token、密码、私钥、验证请求头明文。
35. 步骤配置、强制取消、清理、单步测试可在审计日志查询。
36. 前端仅使用原生 HTML5/CSS3/JavaScript（fetch），无外部前端依赖与 CDN。
37. 重启后 H2 数据仍在，jar 同级生成 `one-build-h2.mv.db`。
38. HTTP 步骤重复调用同一 URL 时，重复触发由执行方保证幂等（已知限制）。
39. SCRIPT 返回 1 会重跑命令，脚本需保证幂等（已知限制）。
40. 推送目标分支不会与 Jenkins SCM 自动触发形成双构建（Job 侧需关闭/过滤）。

## 11. 技术约束

| 项 | 约束 |
|----|------|
| 前端 | 原生 HTML5 + CSS3 + JavaScript（fetch），不使用框架、UI 库、外部依赖与 CDN |
| 后端 | Spring Boot 3 + JDK 17 |
| 工具库 | hutool（HTTP、JSON、字符串、加密等工具） |
| 表达式 | Spring SpEL，受限 `SimpleEvaluationContext` |
| 数据库 | H2 2.x 文件模式（`one-build-h2.mv.db`），不引入外部数据库 |
| git | 服务端安装 git，具备仓库读写与推送权限 |
| 步骤执行 | `ProcessBuilder` + OS shell（Linux `sh -c`，Windows `cmd /c`；可配 shell） |
| 部署形态 | 单机、单实例、内网；H2 嵌入式，不支持多节点 |
| 管理员账号 | 明文配置在 yml，修改需重启 |
| 接口风格 | REST + JSON，统一错误响应结构 |
| 网络 | 内网 HTTP；无需代理/CA/公网 TLS（HTTPS 可选） |

## 12. 风险与已知限制

| 风险/限制 | 说明 | 缓解 |
|-----------|------|------|
| 管理员密码明文 | 能读配置文件即可登录 | 文件权限 600、限制部署目录访问、日志脱敏 |
| 单机单实例 | 不支持多节点、滚动升级 | 文件锁保护；升级停机；H2 备份 |
| 通用 git 无法远程检索 | 添加项目必须提供 URL | 界面提示；后续可扩展平台 Provider |
| 合并冲突需人工处理 | 工具终止合并，不自动解冲突 | 提供目标分支、命令与重试入口 |
| SCRIPT 返回 1 会重跑 | 非幂等脚本可能重复执行 | 文档要求幂等；失败即停；日志可追溯 |
| HTTP 轮询重复请求 | 可能重复触发构建 | 由执行方保证幂等；建议携带 taskId/stepIndex |
| 健康检查不校验版本 | 旧进程健康时可能误判成功 | 用户脚本自行停止旧进程/校验版本；已知限制 |
| Jenkins 双触发 | 推送与工具触发可能各构建一次 | Jenkins 侧关闭 SCM 自动触发或过滤分支 |
| 后台进程管道 | 脚本启动服务未重定向可能导致步骤不结束 | 规范要求重定向 stdout/stderr、关闭管道 |
| Jenkins 回调缺失 | 未实现回调则步骤超时 | 提供模板；超时兜底；可配详情链接 |
| 步骤长执行占用项目锁 | 其他合并/触发被拒绝 | 提示占用任务；管理员可强制取消 |
| 持久 workspace 脏状态 | 残留文件影响构建 | 每次 reset + clean -fd（保留 ignored） |
| 远程凭证 | SSH 私钥/密码泄露风险 | 加密存储、临时文件 600、用后删除、脱敏 |
| SpEL 误配/注入 | 表达式错误或调用越权 | 受限上下文、仅管理员、长度限制、异常按失败 |
| 6 位哈希碰撞 | 概率低但存在 | 自动延长至 8/10 位 |
| 定时清理误删 | 依赖最后使用时间 | 保留最近 10 + 运行中引用保护 + 审计 |
| 脚本权限过大 | 等价服务器命令执行 | 仅管理员可配置，界面告警，最小运行权限 |

## 附录 A：Jenkins 步骤回调示例

触发配置会渲染 `${callbackUrl}`、`${callbackToken}`、`${taskId}`、`stepIndex` 给 Jenkins。

### A.1 Jenkins Pipeline

```groovy
pipeline {
  agent any

  environment {
    ONE_BUILD_CALLBACK = "http://192.0.2.5:8080/api/callback"
    ONE_BUILD_TASK_ID  = "123"
    ONE_BUILD_STEP     = "1"
    ONE_BUILD_TOKEN    = "任务回调令牌"
  }

  stages {
    stage('Build') {
      steps {
        sh './build.sh'
        sh '''
          curl -sS -X POST "$ONE_BUILD_CALLBACK" \
            -H 'Content-Type: application/json' \
            -d "{\"id\":${ONE_BUILD_TASK_ID},\"stepIndex\":${ONE_BUILD_STEP},\"token\":\"${ONE_BUILD_TOKEN}\",\"status\":\"RUNNING\",\"totalSteps\":2,\"currentStep\":1,\"message\":\"build done\"}"
        '''
      }
    }
    stage('Deploy') {
      steps {
        sh './deploy.sh'
      }
    }
  }

  post {
    success {
      sh '''
        curl -sS -X POST "$ONE_BUILD_CALLBACK" \
          -H 'Content-Type: application/json' \
          -d "{\"id\":${ONE_BUILD_TASK_ID},\"stepIndex\":${ONE_BUILD_STEP},\"token\":\"${ONE_BUILD_TOKEN}\",\"status\":\"SUCCESS\",\"totalSteps\":2,\"currentStep\":2,\"externalId\":\"${BUILD_NUMBER}\",\"detailUrl\":\"${BUILD_URL}\",\"message\":\"deploy done\"}"
      '''
    }
    failure {
      sh '''
        curl -sS -X POST "$ONE_BUILD_CALLBACK" \
          -H 'Content-Type: application/json' \
          -d "{\"id\":${ONE_BUILD_TASK_ID},\"stepIndex\":${ONE_BUILD_STEP},\"token\":\"${ONE_BUILD_TOKEN}\",\"status\":\"FAILED\",\"externalId\":\"${BUILD_NUMBER}\",\"detailUrl\":\"${BUILD_URL}\",\"message\":\"build failed\"}"
      '''
    }
  }
}
```

### A.2 通用 Shell 回调

```bash
curl -sS -X POST "http://192.0.2.5:8080/api/callback" \
  -H "Content-Type: application/json" \
  -d '{
    "id": 123,
    "stepIndex": 1,
    "token": "任务回调令牌",
    "status": "SUCCESS",
    "resultCode": 0,
    "externalId": "build-456",
    "detailUrl": "http://ci.example.com/job/456",
    "message": "deploy finished"
  }'
```

说明：

- `id` 为任务 ID，`stepIndex` 为步骤序号，`token` 为触发时下发令牌。
- `status` 仅支持 `RUNNING / SUCCESS / FAILED`；也可直接传 `resultCode`（0/1/其他）。
- 重复/乱序回调幂等，终态不可覆盖。

## 附录 B：冲突处理命令模板

```bash
git clone <repo_url>
cd <repo_dir>

git fetch origin
git checkout <auto_branch>          # 例如 auto_merge/a1_a2_9f2c1a
git merge origin/<conflict_branch>  # 例如 a2

# 手动解决冲突后
git add .
git commit -m "resolve merge conflict for <auto_branch>"
git push origin <auto_branch>
```

完成后回到本工具点击「重试合并」。工具会重新 `fetch`，以远端目标分支为准，跳过已合入分支，继续剩余合并。

- 若没有目标分支推送权限，请联系管理员放行。
- 工具从不强制推送，人工提交会被保留。

## 附录 C：最小部署与运行前置

1. **运行环境**
   - JDK 17；git 已安装且在 `PATH` 中。
   - 单机部署，启动前确认无第二个实例。
2. **数据目录**
   - 默认使用 jar 所在目录；确保运行用户对目录有读写权限（数据库、`repos/`、`workspace/`、`logs/`）。
   - 配置文件权限 `600`。
3. **网络（内网）**
   - 工具可访问：git 仓库地址、HTTP 步骤地址、验证目标地址、Jenkins 地址。
   - Jenkins 可访问 `one-build.security.callback-base-url`。
4. **启动**
   - `java -jar one-build.jar`（或系统服务托管）。
   - 数据目录不可写、端口占用或存在 `one-build.lock` 时快速失败并输出原因。
5. **备份**
   - 停机复制 `one-build-h2.mv.db` 与配置文件；恢复时停机替换后启动。
6. **升级**
   - 停机 → 备份 → 替换 jar → 启动（自动执行兼容迁移）；升级前确认无运行中任务。

## 附录 E：SpEL 判断与安全边界

### E.1 上下文变量

| 变量 | 类型 | 说明 |
|------|------|------|
| `#status` | int | HTTP 状态码 |
| `#body` | String | 响应体（已截断） |
| `#headers` | Map | 响应头 |
| `#attempt` | int | 当前尝试次数 |
| `#elapsed` | long | 本步已耗时（秒） |
| `#env` | String | 环境名 |
| `#project` | String | 项目名 |
| `#autoBranch` | String | 目标分支 |
| `#taskId` | long | 任务 ID |

### E.2 示例

```text
// 成功；404/5xx 继续等；其余失败
#status == 200 && #body.contains('"state":"done"') ? 0 : (#status == 404 || #status >= 500 ? 1 : 2)

// 构建中
#body.contains('"state":"running"') ? 1 : (#body.contains('"state":"done"') ? 0 : 2)
```

### E.3 安全边界

- 仅管理员可配置表达式。
- 使用 `SimpleEvaluationContext`，禁止访问 Bean、类型、静态方法与任意对象方法；仅允许字符串/Map 的受控方法。
- 表达式长度上限（如 1000 字符）。
- 求值异常、非整数结果统一按失败处理并记录原因。
- 表达式与结果写入审计日志（脱敏）。
